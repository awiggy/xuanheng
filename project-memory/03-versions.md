# 版本范围与当前状态

> 读取场景：判断某项属于哪个版本、是否已经实现、下一版本做什么。人工是否通过以根目录 `ACCEPTANCE_CHECKLIST.md` 为准。

## V1.x 四柱八字 — 本地 RC，待联合人工验收

- V1.0 基础闭环：三历录入与换算、地图/时区/真太阳时、确定性排盘、档案历史、去重、编辑、删除、缓存。
- V1.1 命盘研判：四柱、藏干、十神、纳音、五行、神煞与结构化解读。
- V1.2 岁运时间轴：大运顺逆、起运、当前大运、十年流年与定气流月。
- V1.3 问一件事：基于已有命盘，带入原局/大运/流年，保存历史、重开复用、删除和导出。
- V1.4 数据与账户：计划从本机 SQLite 过渡到可部署数据库；账户与同步尚未实施。
- V1.5 上线验收：线上前后端、移动适配、错误/加载/空态/重试、隐私与备份，尚未开始。

## V2.x 塔罗 — 本地 RC，待联合人工验收

- 已接入 78 张牌、正逆位、6 种牌阵、seed/time factor、历史与 Markdown 导出。
- 空问题前后端均拒绝抽牌，不生成解读或历史。
- 正常流程：填写问题 → 选择牌阵 → 牌背入场 → 逐张翻牌 → 全部翻开后解读。
- 模型不可用时提供明确标注的本地结构化解读。
- 后续：移动端体验、安全边界、商业规则和上线验收。

- V3.1 已接入十二宫前端、宫位详情、庙旺、三方四正和出生档案复用。

## V4.x 合缘 — V4.0 RC

- 已实现双档案选择、双方交换、三种观察场景、确定性合冲/五行证据、解释、历史、删除和导出。
- 相同双档案、场景、四柱与规则版本复用缓存。
- 模型只翻译证据为互动模式和现实沟通动作，不得预测关系结局。
- 待人工验收完整闭环与非宿命表达。

## 跨版本原则

- V1/V2/V3/V4 可在同一轮联合验收，但不得因新版本推进而自动把旧版本标记为通过。
- 上线不是静态页面可访问；必须同时覆盖前端、确定性后端、数据库、密钥保护、日志和恢复。
