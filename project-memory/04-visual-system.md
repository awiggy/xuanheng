# 日光之间视觉系统

> 读取场景：前端、布局、组件、响应式、视觉回归和术语统一。当前有效规范；历史变化只见里程碑。

## 当前状态

- 2026-09-21 用户选定 A「日光之间」，明确授权正式首页及内部布局、排版、视觉一起重构；不再停留于概念稿。
- 已实现：正式首页三卡片与真实导航、出生档案/编辑弹窗、四柱结果、岁运、问事与历史抽屉、塔罗全部状态、紫微命盘/报告/运限/历史、合缘、分析服务弹窗和理念页。
- 英文展示名已确认采用 Luma；品牌名称统一配置，不修改后台数据身份。
- 不部署云端。代码与自动检查完成不代表用户验收通过。

## 唯一视觉规则

- 背景浅蓝 `#ebf5ff`，正文深墨 `#17212c`，次级文本 `#5e6a78`，白色阅读卡片；八字淡蓝、塔罗淡紫、紫微淡绿仅作同一系统内的模块区分。
- 全文一个字体栈：PingFang SC / Microsoft YaHei / Helvetica Neue / Arial / sans-serif；标题、正文、数据、眉题、表单和地图控件不另设衬线/等宽字体。
- 主标题桌面 32–48px，正文 14–15px，辅助信息通常 12–13px；首页保留概念稿的大号无衬线展示标题。
- 内容网格最大 1160px，顶栏最大 1320px；桌面正文起点统一。问事阅读列主动收窄，但外层与顶栏坐标保持一致。
- 主按钮深墨底白字，次按钮白底描边，选中为浅蓝/模块粉彩，成功绿、错误红、校准提示暖色；禁用保留明确提示。
- 卡片外层 20–28px 圆角，内部信息块 12–18px，按钮/标签圆角；不用旧金色网格、外层白框和阴影套框。
- 原算法五行色保留语义区分，不能在移除旧主题时抹掉数据色条。
- 问事空态与结果态共享身份、模式、输入、建议和历史入口；塔罗抽牌/翻牌/解读共享工作台。
- 紫微持续明确“排盘校准中，仍待 30 盘对照”，不以完整 UI 冒充算法已校准。

## 文件边界

- `app-layout.css`：从原界面抽离并保留交互几何、可见性、滚轮/地图/翻牌行为；不维护视觉配色。
- `daylight-theme.css`：统一设计 token、排版、内容宽度、共享组件与各业务状态；地图字体显式覆盖外部样式。
- `home-daylight.css`：已选概念 A 的首页视觉，限定在首页内，不能污染功能页。
- `home-cards.js`：卡片点击、拖动、键盘切换及真实子功能导航；不含假数据预览弹窗。
- `brand-config.js` / `daylight-ui.js`：展示名称/浏览器标题及共享品牌标志/线性图标。
- 正式页面不再加载 `night-theme.css`；旧文件仅留作历史回溯。
- 两份原始概念 HTML 保持独立归档；B 未被选用。

## 回归边界

- 独立临时数据库测试，不读取/写入用户真实档案，不请求真实模型。
