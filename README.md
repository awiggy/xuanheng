# 玄衡 · Xuanheng

以「玄夜星图」为统一视觉的传统文化研究应用，集成四柱八字、塔罗占问、紫微斗数与合缘。

**当前状态：本地候选验收版（RC），不是已上线的生产服务。** 代码实现不等于人工验收通过，紫微排盘仍待至少 30 盘对照校准。当前不提供云端账户或跨设备同步。

## 功能概览

| 模块 | 当前实现 |
| --- | --- |
| 出生档案 | 创建、编辑、读取与删除；阳历/阴历/四柱录入，地区、时区与真太阳时校正 |
| 四柱八字 | 四柱、藏干、十神、纳音、五行、神煞与命盘研判 |
| 岁运与问事 | 大运、流年、定气流月；问事意图分流、历史保存与重开 |
| 塔罗占问 | 78 张牌、6 种牌阵、正逆位；先填写问题，再抽牌、翻牌、展示解读；历史重开 |
| 紫微斗数 | 十二宫、主辅星、四化、三方四正、大限与流年、主题解读与历史报告；不提供 Markdown 导出 |
| 合缘 | 选择两份出生档案，计算关系证据并生成报告，支持历史重开 |

出生档案供八字、紫微与合缘复用；塔罗围绕独立问题运行，不读取出生档案。确定性计算与模型解读分层，模型文字不作为排盘计算来源。

## 本地运行

推荐在 **macOS + Python 3** 环境使用。当前模型密钥保存依赖 macOS 钥匙串；其他系统未完成完整适配验收。

```bash
git clone https://github.com/awiggy/xuanheng.git
cd xuanheng
python3 server.py
```

浏览器打开 <http://127.0.0.1:4173/#/home>。服务仅监听本机 `127.0.0.1:4173`。

macOS 也可双击仓库中的 **打开玄衡.command**；或在项目目录运行：

```bash
zsh 打开玄衡.command
```

请保持服务终端运行。关闭终端或按 `Ctrl+C` 停止服务后，页面无法继续排盘或读写档案。

### 初次使用

1. 启动服务，进入「我的档案」创建出生资料。
2. 选择档案进入八字或紫微；合缘需要选择两份档案。
3. 如需模型分析，通过界面的「接入分析 API」或「分析服务」配置服务地址、模型与密钥。
4. 塔罗先填写具体问题，再选择牌阵并抽牌。

基础本地后端及已纳入仓库的排盘脚本使用 Python 标准库；地图、地理编码及外部模型服务需要网络。无模型配置时，部分模块仅提供本地规则报告，不能将其视为完整模型分析。

**不要直接双击 `index.html` 使用产品。** 它依赖 `server.py` 提供的 API。仓库中的 React / Next / Vinext 工程为另一套占位工程，`npm run dev` 不是当前玄衡完整产品的启动入口。

## 数据与隐私

- 档案、历史与缓存保存在本机 `.xuanheng/state.sqlite3`；换一台电脑不会自动同步。
- 模型 API Key 保存于 macOS 钥匙串；调用模型时，相关分析资料会发送到你配置的服务商，请先确认其隐私政策与数据使用方式。
- `.xuanheng/`、环境变量文件及本地密钥不应提交到 Git。仓库已有相应忽略规则。
- 备份资料时，请先停止服务，再私下备份 `.xuanheng/`；源码仓库不是个人资料备份。
- 请勿把当前本地服务直接暴露到公网，它不是具备生产级鉴权与多用户隔离的服务。

## 项目结构

| 路径 | 用途 |
| --- | --- |
| `index.html`、`night-theme.css` | 当前产品界面及玄夜星图样式 |
| `server.py` | 本地 HTTP/API、档案、分析配置与历史管理 |
| `tarot_engine.py` | 塔罗引擎适配与本地解释 |
| `ziwei_engine.py` | 紫微排盘及运限计算 |
| `affinity_engine.py` | 双档案合缘证据计算 |
| `vendor/` | 第三方排盘脚本与参考资料 |
| `tests/test_xuanheng.py` | 后端自动回归测试 |
| `previews/` | 历史视觉方案与交互预览，不是正式入口 |

## 常见问题

**网页能打开，但不能新建或读取档案？** 确认 `python3 server.py` 所在终端仍在运行，并从上面的本地地址访问，而不是 `file://` 或静态页面。

**端口被占用？** 先检查是否已经运行了玄衡，优先使用已有服务；不要盲目结束不明进程。

**修改前端后如何查看？** 保存 HTML/CSS 后刷新浏览器；修改 Python 后端后重启服务。
